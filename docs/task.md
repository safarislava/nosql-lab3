# Вариант №3824

Продолжить разработку приложения из лабораторных работ №1 и №2. Существующие CRUD API и ранее подключённые хранилища должны продолжать работать.

Добавить wide-column систему хранения: Apache Cassandra.
## Дополнительные параметры
- хранимые события: история изменения основных объектов;
- обязательный запрос: события заданного типа за период;
- размер временного бакета: ~~100 000 событий~~ временной период;
- сценарий согласованности: сравнение ONE и ALL; 
- эксперимент с отказом: потеря доступного кворума;
- исследуемый механизм: размер partition и возникновение hot partition.

## Требования к программе
+ Сохранить функциональность первых двух лабораторных и записывать назначенные события в новую систему.
+ Развернуть кластер минимум из трёх узлов с replication factor 3.
+ Спроектировать таблицы от запросов, обосновать partition key, clustering columns и применить назначенное бакетирование.
+ Реализовать запись событий и их чтение с сортировкой и пагинацией, включая обязательный запрос варианта.
+ Создать отдельные денормализованные таблицы минимум для трёх запросов; использование ALLOW FILTERING запрещено.
+ Выполнить назначенный эксперимент с уровнями согласованности и сравнить доступность и задержку операций.
+ Провести назначенный эксперимент с отказом узла и исследовать указанный внутренний механизм.
+ Провести нагрузочный эксперимент, зафиксировав throughput, среднюю задержку и p95.
